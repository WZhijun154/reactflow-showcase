## Codebase Patterns
- **Framework:** Next.js 16 (App Router) with TypeScript, Tailwind CSS 4
- **Tailwind setup:** Uses `@tailwindcss/postcss` plugin (v4 style), import via `@import "tailwindcss"` in globals.css
- **Static export:** `output: "export"` in next.config.ts, images must be `unoptimized: true`
- **basePath:** `/reactflow-showcase` — all links and assets must account for this
- **Google Fonts:** Removed — incompatible with static export. Use system fonts.
- **React Flow:** `@xyflow/react` v12 — import from `@xyflow/react`, styles from `@xyflow/react/dist/style.css`
- **React Flow client component:** Pages using ReactFlow MUST have `"use client"` directive
- **Path alias:** `@/*` maps to `./src/*`
- **Tests:** `node:test` runner with `.test.mts` files in `tests/` directory, run via `npm test`
- **Typecheck:** `npx tsc --noEmit` or `npm run typecheck`
- **Build:** `npm run build` → static output in `out/`
- **Repo:** github.com/WZhijun154/reactflow-showcase
- **Branch:** feature/reactflow-showcase
- **Diagram wiring:** DiagramContainer uses a `switch` on `diagram.id` to render the correct diagram component. Each new diagram type needs a case in DiagramContainer.tsx.
- **Custom node pattern:** Create `src/components/diagrams/<type>/nodes/` directory with individual node components. Each node receives `NodeProps` from `@xyflow/react` and uses `Handle` for connections. Register in a `nodeTypes` object (must be defined outside the component or memoized to avoid re-renders).
- **Diagram data pattern:** Create `src/data/<type>.ts` exporting typed `Node[]` and `Edge[]` arrays. Use `type` field on nodes to match custom `nodeTypes` keys.
- **Node type casting:** Node `data` prop is typed as `Record<string, unknown>`. Cast to a specific interface inside the component: `const nodeData = data as MyNodeData`.
- **Custom shapes via CSS:** Use `clipPath` with `polygon()` for hexagons, parallelograms, etc. Use rounded ellipses (`rounded-[50%]`) for cylinder shapes. Tailwind `transition-all hover:scale-105` for hover effects.
- **Edge styles:** Sync edges use solid `strokeWidth: 2` with color. Async edges add `strokeDasharray: "6 3"`. Use `markerEnd: { type: "arrowclosed", color }` for arrow markers.
- **Tier-based coloring:** Use a `tierColors` lookup object mapping tier names to Tailwind class strings (bg, border, badge) for consistent color theming.
- **Category coloring pattern:** Use a `categoryColors` lookup object mapping category names to `{ bg, border, text }` Tailwind classes. Works for concept maps, org charts, and other category-based diagrams.
- **Importance/size-based styling:** Use an `importanceSizes` lookup mapping importance levels to Tailwind class strings for varying node sizes (min-w, padding, text-size).
- **Barrel exports:** Each diagram's `nodes/` directory has an `index.ts` barrel file re-exporting all node components.
- **Level-based coloring:** Use a `levelColors` lookup object mapping hierarchy level numbers to `{ border, accent, avatar }` Tailwind class strings. Works for org charts and hierarchical diagrams.
- **Avatar initials:** Use a `getInitials()` helper to extract first letters from a name for avatar placeholders.
- **Depth-based sizing:** Use a `depthStyles` lookup mapping depth levels to `{ bg, border, text, size }` Tailwind class strings for nodes that decrease in size with depth (e.g., mind maps).
- **Zone-based coloring:** Use a `zoneColors` lookup mapping zone names (external, dmz, internal) to `{ border, badge }` Tailwind class strings. Works for network diagrams with security zones.
- **State machine node types:** Use distinct visual styles per state type: initial (filled circle, source-only handle), regular (rounded rectangle with label+description), final (double circle, target-only handle).
- **Handle direction semantics:** Initial/start nodes have only source handles. Final/end nodes have only target handles. Regular nodes have both. Use named handle IDs (e.g., "right", "left") for non-standard edge routing.
